QTT Tensor Engine - Installation Guide
====================================

Overview
--------
The application has two local services:

1. Frontend: Next.js, served on port 3000
2. Backend API: FastAPI, served on port 8000

The backend runs Wolfram Language scripts to perform tensor calculations. Both
services must be running to use the application.


Prerequisites
-------------
- Git
- Node.js 18 or newer and npm
- Python 3.10 or newer
- Wolfram Engine or Mathematica, with a valid license/entitlement

Install Wolfram Engine or Mathematica separately, following Wolfram's installation
and licensing instructions. The executable named "wolfram" (or "wolfram.exe" on
Windows) must be available on PATH before you start the backend. Without a working
Wolfram installation and license, the website and API can start, but calculations
will fail.


1. Clone the repository
-----------------------

git clone https://github.com/synsrk12/qtt-tensor-engine.git
cd qtt-tensor-engine


2. Configure Wolfram
--------------------

Linux/macOS

Make sure the directory containing the "wolfram" executable is on PATH. For
example, add the appropriate Wolfram installation directory to your shell profile,
then open a new terminal. Check that the command is discoverable:

command -v wolfram

Windows PowerShell

The Mathematica installer commonly places wolfram.exe in a versioned directory
such as:

C:\Program Files\Wolfram Research\Mathematica\13.0

Adjust the path to match your installed version. To make it available in the
current PowerShell session only, run:

$env:Path = "C:\Program Files\Wolfram Research\Mathematica\13.0;$env:Path"
Get-Command wolfram

For future terminal sessions, add the directory containing wolfram.exe to your
Windows user or system PATH using Environment Variables, then open a new terminal.
Start the backend from a terminal where `Get-Command wolfram` succeeds. A PATH
change made after the backend starts does not affect that running backend.

If Wolfram provides a separate `wolframscript` command, that alone is not enough:
this backend launches `wolfram -script`. Ensure the `wolfram` executable itself
is discoverable on PATH.


3. Install and run the backend
------------------------------

Open a terminal in the repository root, then:

Linux/macOS

cd TnsrBackend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install fastapi uvicorn pydantic
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

Windows PowerShell

cd TnsrBackend
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install fastapi uvicorn pydantic
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

If PowerShell prevents virtual-environment activation, you can skip activation
and use the environment's Python executable directly:

.\.venv\Scripts\python.exe -m pip install fastapi uvicorn pydantic
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

The backend API is at http://127.0.0.1:8000. Interactive API documentation is at
http://127.0.0.1:8000/docs.


4. Install and run the frontend
-------------------------------

Open a second terminal in the repository root:

Linux/macOS

cd Project_bolt/project
npm ci
npm run dev

Windows PowerShell

cd Project_bolt\project
npm.cmd ci
npm.cmd run dev

Open http://localhost:3000 in your browser. Keep both services running while
using the application.


5. Optional production build
----------------------------

From Project_bolt/project:

npm run build
npm run start


6. Troubleshooting
------------------

Frontend command not found
- Install Node.js 18 or newer, then open a new terminal.
- Check availability with `node --version` and `npm --version`.

Backend command or import errors
- Confirm you are using Python 3.10 or newer and the backend virtual environment.
- Install dependencies with `python -m pip install fastapi uvicorn pydantic`.
- Run the app from the TnsrBackend directory with
  `uvicorn app.main:app --reload --host 127.0.0.1 --port 8000`.

Calculation errors mentioning Wolfram or a missing executable
- Confirm Wolfram Engine or Mathematica is installed and its license is active.
- Confirm `wolfram` is on PATH in the same terminal used to start the backend.
- On Windows, use `Get-Command wolfram` to check command discovery.
- After changing PATH, stop and restart the backend from a terminal with the
  updated PATH.

Port already in use
- Stop the other service using port 3000 or 8000, or configure the application
  and frontend proxy to use matching alternate ports.

The frontend forwards calculation requests to http://127.0.0.1:8000. Keep the
backend at that address unless you also update the frontend API route.
